## Implementation

The new lossless codec groups 96 stickers into 8 corners, 24 wings, and 24 centres. Each corner/wing position admits 24 reachable colour tuples (5 bits); each centre has six colours (3 bits). The total is 232 bits, or 29 bytes. Piece transitions are exhaustively generated from the original move table. All-zero packed state is reserved for padding.

The streamed selection loop carries scores and child IDs. It materializes winner states once, applies moves directly to packed piece codes, and sends three typed buffers: 29-byte states, 4-byte parent/move metadata, and 2-byte bf16 scores. The logical record is 35 bytes versus the original 128-byte record. Received-state decode, hashing, gather and endgame checks run in bounded tiles. These byte counts do not predict physical XLA padding or total HBM by themselves.

Backpointers preserve the original uint64 layout: 25 local-parent bits, 3 rank bits, 5 move bits. A 60-level tree needs 128,849,018,880 bytes (120 GiB) and is placed under `/tmp`, outside Kaggle output storage. The wrapper checks compiled program memory against 15,000,000,000 bytes per chip before allocating the full frontier. This is a conditional execution guard, not measured proof of fit.

The source model and endgame modules are copied unchanged. The runner is generated from the source notebook's setup, data loading, endgame, search, path reduction, replay, and min-merge cells. Endgame cache files include hashes of their inputs, builder, and generated arrays.
