### P1.1 — Thistlethwaite-style two/three-phase decomposition for Megaminx

**Hypothesis.** Rubik's cube's God-number proof relies on Thistlethwaite's 4-stage chain
G_0 ⊃ G_1 ⊃ G_2 ⊃ G_3 with stage diameters ~6-12. Kociemba's 2-phase variant achieves
near-optimal in ~20 moves. **No published Megaminx chain exists.** If we derive one with
stage diameters ≤8, we can BFS each stage exactly: a solve becomes K stage-BFS lookups, each
≤8 moves → potentially 5×8 = 40 total moves vs our current 88.

**Why bold.** Blank-slate territory. The icosahedral group has order 60 with non-trivial
proper subgroups; the subgroup lattice IS computable. Even a 3-stage decomposition with
diameters 12+10+8 = 30 moves would crush the LB.

**Concrete spike (week 1).** Pure investigation, no training:
- Compute the icosahedral group's normal subgroup lattice using GAP or sympy.combinatorics.
- Propose 2-3 candidate stage chains. For each:
  - Identify the restricted generator set per stage (which subset of the 24 gens preserves
    the invariants of the prior stage).
  - BFS-exhaust each stage. Stage diameter ≤10 = exploitable.
- Decide go/no-go after one week.

**Code sketch — feasibility probe via sympy.combinatorics:**

```python
from sympy.combinatorics import PermutationGroup, Permutation
import json
from collections import deque


def load_megaminx_generators(path: str):
    with open(path) as f:
        info = json.load(f)
    return {name: Permutation(perm) for name, perm in info["generators"].items()}


def compute_subgroup_invariants(gens: dict, stage_invariant_fn):
    """Return the subset of generators that preserve the stage_invariant_fn."""
    preserved = {}
    identity_state = list(range(120))
    for name, g in gens.items():
        # Apply g to identity, check if invariant preserved.
        moved = [g(i) for i in range(120)]
        if stage_invariant_fn(identity_state, moved):
            preserved[name] = g
    return preserved


def bfs_stage_diameter(gens: dict, max_depth: int = 12) -> tuple[int, int]:
    """Compute exact diameter of the subgroup generated by gens, up to max_depth.
    Returns (diameter, total_states). Bails at max_depth."""
    n = 120
    identity = tuple(range(n))
    seen = {identity: 0}
    frontier = deque([identity])
    while frontier:
        s = frontier.popleft()
        d = seen[s]
        if d >= max_depth:
            return d, len(seen)
        for name, g in gens.items():
            ns = tuple(g(i) for i in s)
            if ns not in seen:
                seen[ns] = d + 1
                frontier.append(ns)
    return max(seen.values()), len(seen)


# Example stage 1 invariant: "all 12 face centers are correctly oriented"
# (centers are positions {0, 11, 22, 33, ...} — the ACTUAL center positions depend
# on the puzzle.json layout; this is a sketch).
def stage1_invariant(s_orig, s_new):
    centers = [0, 11, 22, 33, 44, 55, 66, 77, 88, 99, 110]
    return all(s_new[c] == s_orig[c] for c in centers)


if __name__ == "__main__":
    gens = load_megaminx_generators("data/puzzle_info.json")
    print(f"Total generators: {len(gens)}")
    # Stage 2 generator subset: only those that preserve oriented centers.
    stage2_gens = compute_subgroup_invariants(gens, stage1_invariant)
    print(f"Stage 2 generators: {len(stage2_gens)}")
    diam, n_states = bfs_stage_diameter(stage2_gens, max_depth=8)
    print(f"Stage 2 diameter ≤ {diam}; reached {n_states:,} states")
```

**Effort.** L (1-2 weeks of group-theory work + decomposition design + per-stage BFS build).
**Risk.** M-L. Megaminx's icosahedral group is harder to factor than Rubik's octahedral group;
a useful chain may not exist or may have impractical stage diameters.

**Payoff.** **HUGE.** A working 3-stage decomposition could plausibly reach 50-60K total moves.

### P1.2 — Stream-of-Search: train a transformer to OUTPUT search trajectories

**Hypothesis.** Stream-of-Search (Gandhi 2024, arxiv 2404.03683) trains a transformer to
emit its own search process as a token sequence: `state_0 → try a_5 → V=82 → backtrack → try a_12 → V=79 → ...`. The model learns search itself as a generation task. For Megaminx
this means: scrambled state in, full move sequence out, no beam loop required at inference.

**Why bold.** Bypasses the entire greedy-beam paradigm. The model can backtrack within its
own forward pass. AlphaProof works this way for IMO problems.

**Concrete spike.**
- Collect 100K solved (state, move sequence) pairs from current m05 + qshort beam.
- Tokenize: 120 state-tokens (vocab=120) + 24 action-tokens (vocab=24) + special tokens
  (BOS, EOS, BACKTRACK).
- Train a 6-layer transformer decoder. Input: scrambled state. Output: action sequence (or
  state-action interleaved).
- Inference: greedy or nucleus-sample the action sequence; verify; pick shortest across N
  samples.

**Code sketch:**

```python
import torch
import torch.nn as nn


class StreamOfSearchTransformer(nn.Module):
    """Decoder-only transformer. Input: scrambled state encoded as 120 tokens.
    Output: action sequence ending in EOS, optionally interleaved with STATE markers.

    Vocabulary: 120 state-value tokens + 24 action tokens + {BOS, EOS, BACKTRACK} = 147."""
    def __init__(self, vocab_size: int = 147, d_model: int = 384,
                 n_heads: int = 6, n_layers: int = 6, max_len: int = 512):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, d_model)
        self.pos = nn.Parameter(torch.randn(1, max_len, d_model) * 0.02)
        decoder_layer = nn.TransformerDecoderLayer(
            d_model=d_model, nhead=n_heads, dim_feedforward=1536,
            batch_first=True, norm_first=True, activation="gelu",
        )
        self.decoder = nn.TransformerDecoder(decoder_layer, n_layers)
        self.head = nn.Linear(d_model, vocab_size)
        self.max_len = max_len

    def forward(self, tokens, memory=None):  # tokens: (B, L)
        x = self.embed(tokens) + self.pos[:, : tokens.size(1)]
        causal = nn.Transformer.generate_square_subsequent_mask(tokens.size(1)).to(tokens.device)
        if memory is None:
            memory = x  # decoder-only: attend to own past
        out = self.decoder(x, memory, tgt_mask=causal)
        return self.head(out)

    @torch.no_grad()
    def generate(self, scrambled_state_tokens, max_new_tokens: int = 200,
                 temperature: float = 0.7):
        tokens = scrambled_state_tokens.clone()
        for _ in range(max_new_tokens):
            logits = self.forward(tokens)[:, -1, :] / temperature
            probs = torch.softmax(logits, dim=-1)
            next_tok = torch.multinomial(probs, 1)
            tokens = torch.cat([tokens, next_tok], dim=1)
            if (next_tok == 146).all():  # EOS token
                break
        return tokens
```

Training data preparation:

```python
def encode_solve_for_sos(state, move_names, action_to_idx, state_offset=27):
    """Encode (state, [move names]) as token sequence for training.
    Format: [BOS, state[0], ..., state[119], action_0, action_1, ..., EOS]
    Token IDs: 0=BOS, 1=EOS, 2..25=actions, 27..146=state values (120 vocab)."""
    BOS, EOS = 0, 1
    tokens = [BOS]
    tokens.extend(int(v) + state_offset for v in state)
    tokens.extend(action_to_idx[m] + 2 for m in move_names)
    tokens.append(EOS)
    return tokens
```

**Effort.** L (1-2 weeks: data collection, training, inference loop).
**Risk.** M. Hallucination: model may emit invalid moves. Mitigate via verification + retry.
**Payoff.** **HUGE.** 12-18% potential per Gandhi 2024.

### P1.3 — RL fine-tune of m05 with PPO on the actual objective

**Hypothesis.** m05 is trained to minimize MSE on walk-depth labels (a noisy proxy). The
competition objective is total move count. Fine-tune m05 with PPO using episode reward
`-1 per move + 100 on solve`. This DIRECTLY optimizes what the leaderboard scores. The
two objectives are correlated but not identical — PPO can shift m05 to a strictly better
optimum.

**Why bold.** We have NEVER trained on the actual objective. Every prior model trained on
proxies (RW depth, Bellman bootstrap, BFS distance). Direct RL from m05 = first time we
see the real loss surface.

**Concrete spike.**
- Use CleanRL's PPO baseline (~200 lines).
- Policy = softmax over 24 actions from m05's V (via -V over neighbors).
- Value baseline = m05's V (frozen for first 100 epochs, then trainable).
- Episode = scrambled state → beam-or-greedy rollout to terminal (solved or max_steps=150).
- Reward shaping: `r = -1 + (V(s) - V(s'))` (potential-based, preserves optimal policy
  per Ng et al 1999, denser signal).

**Code sketch — PPO training loop:**

```python
import torch
import torch.nn.functional as F
from torch.distributions import Categorical


def ppo_step(policy, value, optim_pi, optim_v, batch, eps_clip: float = 0.2,
             vf_coef: float = 0.5, ent_coef: float = 0.01):
    """One PPO update on a batch of (states, actions, old_log_probs, returns, advantages).
    """
    states, actions, old_log_probs, returns, advs = batch
    advs = (advs - advs.mean()) / (advs.std() + 1e-8)

    logits = policy(states)
    dist = Categorical(logits=logits)
    new_log_probs = dist.log_prob(actions)
    entropy = dist.entropy().mean()

    ratio = (new_log_probs - old_log_probs).exp()
    surr1 = ratio * advs
    surr2 = torch.clamp(ratio, 1 - eps_clip, 1 + eps_clip) * advs
    pi_loss = -torch.min(surr1, surr2).mean()
    v_loss = F.mse_loss(value(states).squeeze(-1), returns)
    loss = pi_loss + vf_coef * v_loss - ent_coef * entropy

    optim_pi.zero_grad(); optim_v.zero_grad()
    loss.backward()
    optim_pi.step(); optim_v.step()
    return float(pi_loss.item()), float(v_loss.item()), float(entropy.item())


def collect_rollout(policy, puzzle, scrambled_state, generators, solved_state,
                    max_steps: int = 150, device: str = "cuda"):
    """Single-episode rollout. Returns lists of (state, action, reward, log_prob, value)."""
    state = torch.tensor(list(scrambled_state), dtype=torch.int64, device=device)
    states, actions, rewards, log_probs = [], [], [], []
    for t in range(max_steps):
        logits = policy(state.unsqueeze(0)).squeeze(0)
        dist = Categorical(logits=logits)
        a = dist.sample()
        states.append(state.clone())
        actions.append(a)
        log_probs.append(dist.log_prob(a))
        # Apply move.
        next_state = state[generators[a.item()]]
        # Reward: -1 per move, +100 on solve.
        if torch.equal(next_state, solved_state):
            rewards.append(99.0)  # net +100 - 1 step penalty
            states.append(next_state)
            break
        rewards.append(-1.0)
        state = next_state
    return states, actions, rewards, log_probs
```

**Effort.** M-L (1 week). CleanRL is ~200 lines off-the-shelf; integration is straightforward.
**Risk.** M. PPO with sparse reward famously slow; need careful reward shaping.
**Payoff.** 5-10% per agent estimate. Could be larger if proxy↔objective gap is meaningful.

### P1.4 — Speedcubing macro library + neural beam (HYBRID)

**Hypothesis.** WCA-record Megaminx solvers use ~200-250 moves via human-engineered macros
(Megaminx CFOP, Roux variants, Westlund method). These macros — OLL/PLL last-layer algorithms,
F2L pair-up sequences — are PUBLIC at speedsolving.com, AlgDB, jPerm. Each macro is 5-15
moves. **Treat each macro as a meta-action in beam search.**

**Why bold.** Decades of speedcubing community knowledge encoded as ~200 named algorithms.
Neural beam treats them as black-box actions; effective branching factor goes from 24 to
24+M (M ≈ 100-200), but path length plummets.

**Concrete spike (week 1):**
- Scrape ~100 well-known Megaminx algorithms from cubingdb.com / speedsolving.com.
- Validate each: apply to solved cube, save resulting state. Each algorithm is now (state →
  state) macro.
- Extend the action space in `KhoruzhiiSolver`: instead of 24 generators, expose 24 + 100
  meta-actions where each meta-action's "transition" is a precomputed permutation.
- Inference: any time the beam can apply a macro that gets close to a sub-goal (cycle
  structure recognized), it can do so.

**Code sketch — macro library data structure:**

```python
import json
from pathlib import Path
import numpy as np


class MegaminxMacro:
    """A named macro: a sequence of generators that achieves a known transformation."""
    def __init__(self, name: str, move_names: list, puzzle):
        self.name = name
        self.move_names = move_names
        self.length = len(move_names)
        # Precompute the resulting permutation when applied to identity.
        s = list(puzzle.solved_state)
        for m in move_names:
            s = list(puzzle.apply_move(s, m))
        self.permutation = np.array(s, dtype=np.int8)

    def apply_to(self, state: np.ndarray) -> np.ndarray:
        """Apply this macro to an arbitrary state."""
        return state[self.permutation]


def load_macro_library(json_path: str, puzzle) -> list[MegaminxMacro]:
    """Load a JSON of {name: [move_name, ...]} macros."""
    with open(json_path) as f:
        data = json.load(f)
    return [MegaminxMacro(name, moves, puzzle) for name, moves in data.items()]


# Sample macros.json (would be much larger):
SAMPLE_MACROS = {
    "Sune_R": ["R", "U", "-R", "U", "R", "U", "U", "-R"],
    "AntiSune_R": ["-R", "-U", "R", "-U", "-R", "-U", "-U", "R"],
    "T-perm": ["R", "U", "-R", "-U", "-R", "F", "R", "R", "-U", "-R", "-U", "R", "U", "-R", "-F"],
    # ... 100+ more from speedcubing community
}
```

Beam integration: at each beam expansion, in addition to 24 single-move children, spawn M
"macro-children" by applying each macro. Each macro-child carries its full move sequence
(length 5-15) for path reconstruction.

```python
def expand_with_macros(state: np.ndarray, generators: np.ndarray,
                        macros: list[MegaminxMacro]):
    """Generate (24 + len(macros)) children: 24 single moves + M macros."""
    # Single-move children (existing logic).
    single_children = state[generators]   # (24, 120)
    # Macro children.
    macro_children = np.stack([m.apply_to(state) for m in macros])  # (M, 120)
    return np.concatenate([single_children, macro_children], axis=0)
```

**Effort.** M (3-5 days: scrape + validate + integrate).
**Risk.** S. Macros are mathematical truths; can't make solutions WORSE if used optionally.
**Payoff.** **HUGE.** Could deliver -10K to -20K total moves directly.

### P1.5 — Coset Pattern Databases (admissible heuristic for A* / IDA*)

**Hypothesis.** Korf's PDBs partition state space by subset (e.g., "corner positions only"),
BFS the subset exactly, store distance lookup. Sum of disjoint PDB distances is admissible
(lower bound on full distance). For Megaminx: build a corner-only PDB (~10⁹ states fits in
4 GB at 64-bit hash → 1-byte distance). Combined with edge-only PDB and center-only PDB,
sum gives admissible heuristic that's far tighter than current Hamming/BFS-d6.

**Why bold.** Unlocks IDA* (admissible) which could beat beam on hard puzzles. Currently
all our heuristics are inadmissible (m05 overestimates / underestimates unpredictably).

**Concrete spike.**
- Identify Megaminx pieces: 12 centers + 30 edges + 20 corners = 62 pieces. Each has ~5
  position bits.
- Pick subset (e.g., 5 corners). State space = 5! × 5⁵ orientations ≈ 600K. BFS exactly,
  store distance per state.
- Verify admissibility on BFS-d6 ground truth: PDB(s) ≤ true_distance(s) for all s.

**Code sketch — corner-PDB build:**

```python
from collections import deque
import numpy as np


def project_to_corner_subset(full_state: np.ndarray, corner_indices: list) -> bytes:
    """Project state to subset of corner positions; return canonical byte key."""
    return full_state[corner_indices].tobytes()


def build_corner_pdb(puzzle, corner_indices: list, max_depth: int = 20) -> dict:
    """BFS from solved, projecting to corner subset. Multiple full states map to same
    projected key; store the MINIMUM distance.
    """
    gens = {n: np.array(p, dtype=np.int8) for n, p in puzzle.generators.items()}
    solved = np.array(puzzle.solved_state, dtype=np.int8)
    start_key = project_to_corner_subset(solved, corner_indices)
    pdb: dict[bytes, int] = {start_key: 0}

    frontier = deque([(solved, 0)])
    while frontier:
        s, d = frontier.popleft()
        if d >= max_depth:
            continue
        for name, g in gens.items():
            ns = s[g]
            key = project_to_corner_subset(ns, corner_indices)
            if key not in pdb:
                pdb[key] = d + 1
                frontier.append((ns, d + 1))
    print(f"Corner PDB: {len(pdb):,} states, max depth {max(pdb.values())}")
    return pdb


def pdb_lookup_admissible(state: np.ndarray, pdbs: list[tuple[list, dict]]) -> int:
    """Return sum-of-PDB distances for the state. Admissible if PDBs are on disjoint subsets."""
    total = 0
    for indices, pdb in pdbs:
        key = project_to_corner_subset(state, indices)
        total += pdb.get(key, 0)  # 0 if state outside PDB coverage; conservative
    return total
```

Use as A* / IDA* heuristic h(s) = pdb_lookup_admissible(s); g(s) = path length so far;
f(s) = g + h.

**Effort.** M (1 week).
**Risk.** M. Subset selection matters; admissibility is mathematically guaranteed once correct.
**Payoff.** HUGE if A*/IDA* works. Even MEDIUM if used as beam re-ranker.

### P2.1 — Insertion-Finder port (FMC competition tool)

**Hypothesis.** The Fewest-Moves competition (FMC) speedcubing community uses tools like
xtqxk's `insertion_finder`. They enumerate factorizations of sub-permutations and try
inserting known sequences at every position in a candidate path; keep insertions that
shorten net length after cancellation. Reportedly saves 5-15 moves per Rubik's solution.

**Why bold.** Free post-processing on every submission, with no model retraining.

**Concrete spike.** Port insertion_finder's logic to Megaminx:
- For each gap in the solution path, try every commutator/conjugate from a precomputed library.
- Re-run the same-face / inverse-cancellation pass after each insertion.
- Accept only if total length strictly decreases.

```python
# Skeleton — sub-routine of full_post_process
def try_insert_macros(path: list, puzzle, macros: list, max_gain: int = 20) -> list:
    """For each position i in path, try inserting each macro and re-canonicalizing.
    Return the shortest variant found."""
    from megaminx.post_process import full_post_process
    best = list(path)
    for i in range(len(path) + 1):
        for macro in macros:
            candidate = best[:i] + macro.move_names + best[i:]
            # Re-canonicalize (cancellations may chain).
            canonical = full_post_process(candidate, puzzle=puzzle)
            if len(canonical) < len(best):
                # Verify: applying canonical from the puzzle's initial state still solves.
                # Caller responsibility to verify.
                best = canonical
    return best
```

**Effort.** M (3-4 days port).
**Risk.** S — purely additive, won't lengthen any path.
**Payoff.** MEDIUM-HUGE: -3K to -10K total moves expected based on FMC community track record.

### P2.4 — Schreier-Sims for short-word lower bounds

**Hypothesis.** Schreier-Sims algorithm (1970, computational group theory) computes a strong
generating set for a permutation group, enabling fast membership tests AND short-word
generation for any group element. For Megaminx subgroups (corner-only, edge-only), it gives
a distance lower bound usable as A*/IDA* heuristic.

**Concrete spike.** Use sympy.combinatorics or GAP:

```python
from sympy.combinatorics import PermutationGroup, Permutation


def schreier_sims_word(group: PermutationGroup, target: Permutation) -> list:
    """Express `target` as a short word in the group's strong generators."""
    if not group.contains(target):
        return None
    return group.subgroup_search(lambda g: g == target)  # rough sketch
```

**Effort.** M (1 week).
**Risk.** M. Full Megaminx group too large; only subgroups are tractable.
**Payoff.** MEDIUM. Same use case as PDBs (P1.5) but different construction.

### P2.5 — Megaminx commutator library

**Hypothesis.** Commutators `[A, B] = ABA⁻¹B⁻¹` and conjugates have algebraic properties
(local effect, often cancel cleanly). Speedcubers use these for last-layer manipulation.
Pre-compute a library of useful commutators; use as macro actions in beam (or as
insertion-finder candidates per P2.1).

**Code sketch:**

```python
def enumerate_commutators(puzzle, max_word_length: int = 4) -> list:
    """Generate all commutators [A, B] where A, B are short words."""
    from itertools import product
    gens = list(puzzle.move_names)
    commutators = []
    for la in range(1, max_word_length + 1):
        for lb in range(1, max_word_length + 1):
            for A in product(gens, repeat=la):
                for B in product(gens, repeat=lb):
                    # [A, B] = A . B . A^-1 . B^-1
                    A_inv = [puzzle.inverse_name(m) for m in reversed(A)]
                    B_inv = [puzzle.inverse_name(m) for m in reversed(B)]
                    word = list(A) + list(B) + A_inv + B_inv
                    # Compute resulting permutation; keep only if it has small support.
                    s = list(puzzle.solved_state)
                    for m in word:
                        s = list(puzzle.apply_move(s, m))
                    diff_count = sum(1 for i, v in enumerate(s) if v != puzzle.solved_state[i])
                    if 0 < diff_count <= 6:  # local-effect commutator
                        commutators.append({"word": word, "support_size": diff_count,
                                            "name": f"[{'.'.join(A)},{'.'.join(B)}]"})
    return commutators
```

**Effort.** M (1 week to enumerate + filter useful ones).
**Risk.** M. Combinatorial explosion; need careful filtering.
**Payoff.** MEDIUM. Probably -50 to -300 moves total via insertion-finder usage.

### P3.1 — Goal-conditioned policy with HER

**Hypothesis.** Currently `g = solved_state` is hardcoded. Generalize to π(a | s, g) — works
for arbitrary (s, g) pairs. Hindsight Experience Replay (Andrychowicz 2017): every random
walk gives a free labeled trajectory by relabeling intermediate states as "achieved goals".

**Why bold.** Enables true LEARNED bidirectional search: forward π targets midpoint, backward
π targets midpoint, both use same model. Currently MITM uses static BFS shell only.

**Code sketch — HER training loop:**

```python
import torch
import torch.nn.functional as F


def her_relabel(trajectory: list, k_relabels: int = 4):
    """Given a trajectory [(s_0, a_0, s_1), ..., (s_T)], produce K relabeled tuples per
    step where the goal is some future state from the same trajectory.
    """
    relabeled = []
    T = len(trajectory)
    for t in range(T - 1):
        s_t, a_t, s_next = trajectory[t]
        # Relabel: pick K future states as substitute goals.
        for _ in range(k_relabels):
            goal_idx = torch.randint(t + 1, T, (1,)).item()
            g = trajectory[goal_idx][0] if goal_idx < T else trajectory[T-1][2]
            # Reward: 0 if next state == goal, else -1.
            r = 0.0 if torch.equal(s_next, g) else -1.0
            relabeled.append((s_t, a_t, s_next, r, g))
    return relabeled


class GoalConditionedPolicy(torch.nn.Module):
    """π(a | s, g): concat state + goal, predict action distribution."""
    def __init__(self, state_size: int = 120, n_actions: int = 24, d_hidden: int = 512):
        super().__init__()
        self.embed_s = torch.nn.Embedding(state_size, 16)
        self.embed_g = torch.nn.Embedding(state_size, 16)
        self.body = torch.nn.Sequential(
            torch.nn.Linear(state_size * 32, d_hidden), torch.nn.ReLU(),
            torch.nn.Linear(d_hidden, d_hidden), torch.nn.ReLU(),
        )
        self.head = torch.nn.Linear(d_hidden, n_actions)

    def forward(self, s, g):
        es = self.embed_s(s.long()).flatten(start_dim=1)
        eg = self.embed_g(g.long()).flatten(start_dim=1)
        return self.head(self.body(torch.cat([es, eg], dim=-1)))
```

**Effort.** L (2 weeks).
**Risk.** L. Goal embedding for n=120 might not generalize.
**Payoff.** 10-20% potential per agent estimate.

### P3.2 — GFlowNet for diverse short-path sampling

**Hypothesis.** GFlowNet (Bengio 2021, 2023) trains forward and backward policies such that
trajectories are sampled with probability proportional to `exp(reward)`. Set
`reward = exp(-path_length)` → samples diverse near-optimal paths. For Megaminx: sample N
paths in parallel, take shortest.

**Why bold.** Fundamentally different sampling regime than greedy beam; explicitly diverse.

**Concrete spike.** Use Bengio lab's torchgfn library (https://github.com/saleml/torchgfn).
Define forward step = apply generator; terminal state = solved. Train with detailed-balance
loss.

```python
# Sketch using torchgfn's trajectory loss
def gflownet_step(forward_model, backward_model, scrambled, solved,
                  generators, max_steps: int = 150):
    """Sample one trajectory; compute log forward / log backward / log reward / loss."""
    state = scrambled
    log_pf = 0.0
    log_pb = 0.0
    actions = []
    for _ in range(max_steps):
        logits = forward_model(state.unsqueeze(0)).squeeze(0)
        probs = torch.softmax(logits, dim=-1)
        a = torch.multinomial(probs, 1).item()
        log_pf = log_pf + torch.log(probs[a] + 1e-8)
        actions.append(a)
        state = state[generators[a]]
        if torch.equal(state, solved):
            break
    # Backward log prob: probability of reverse path under backward model.
    # ... (parallel computation)
    log_R = -float(len(actions))   # reward = exp(-path_length); log_R = -path_length
    # Trajectory balance loss: (log_pf - log_pb - log_R)^2
    loss = (log_pf - log_pb - log_R) ** 2
    return loss, actions
```

**Effort.** L (2-3 weeks, including torchgfn integration).
**Risk.** L. GFlowNet on permutation puzzles is unproven.
**Payoff.** 8-12% per agent estimate.

**Code sketch:**

```python
def build_oracle_q_dataset(puzzle, bfs_table, generators):
    """For each state in BFS-d6, compute the true Q for each of 24 actions.
    Q*(s, a) = 1 + true_distance(apply(s, a)).  
    """
    samples = []
    for state_bytes, path_bytes in bfs_table.table.items():
        state = np.frombuffer(state_bytes, dtype=np.int8)
        d_state = len(path_bytes)
        q_star = np.full(len(generators), float('inf'), dtype=np.float32)
        for a, g in enumerate(generators):
            child = state[g]
            child_path = bfs_table.table.get(child.tobytes())
            if child_path is not None:
                q_star[a] = 1.0 + len(child_path)
        samples.append((state, q_star))
    return samples
```

### P4.1 — Local search on completed paths (SA / LAHC / 2-opt)

**Hypothesis.** Beam search produces 88-move paths via greedy choices. Post-hoc, we can
randomly perturb the move sequence (insert/delete/swap) and accept via simulated annealing
or late-acceptance hill climbing. Different from BFS-d6 windows: explores non-monotonic
local moves.

**Why bold.** Standard for TSP; never tried on permutation-puzzle paths in our pipeline.

**Code sketch — SA on path:**

```python
import math
import random


def verify_path(puzzle, initial_state, path: list) -> bool:
    s = tuple(initial_state)
    for m in path:
        s = puzzle.apply_move(s, m)
    return puzzle.is_solved(s)


def random_neighbor(path: list, puzzle) -> list:
    """One of: delete a random pair (move + its inverse if adjacent), insert a random move,
    swap two adjacent moves."""
    op = random.choice(["delete_pair", "insert_random", "swap_adj"])
    if op == "delete_pair" and len(path) >= 2:
        i = random.randrange(len(path) - 1)
        if path[i] == puzzle.inverse_name(path[i + 1]):
            return path[:i] + path[i + 2:]
    elif op == "insert_random":
        i = random.randrange(len(path) + 1)
        m = random.choice(puzzle.move_names)
        return path[:i] + [m] + path[i:]
    elif op == "swap_adj" and len(path) >= 2:
        i = random.randrange(len(path) - 1)
        new = list(path)
        new[i], new[i + 1] = new[i + 1], new[i]
        return new
    return list(path)


def simulated_annealing_path(puzzle, initial_state, path: list,
                              n_iters: int = 5000, T_start: float = 5.0,
                              T_end: float = 0.1) -> list:
    """SA on the move sequence. Maintains `path` valid (verifies on each accept)."""
    cur = list(path)
    best = list(path)
    cur_len = len(cur)
    best_len = cur_len
    for it in range(n_iters):
        T = T_start * (T_end / T_start) ** (it / n_iters)
        cand = random_neighbor(cur, puzzle)
        if not verify_path(puzzle, initial_state, cand):
            continue
        cand_len = len(cand)
        delta = cand_len - cur_len
        if delta <= 0 or random.random() < math.exp(-delta / T):
            cur, cur_len = cand, cand_len
            if cur_len < best_len:
                best, best_len = list(cur), cur_len
    return best
```

Apply this to every solved path before submission. Wall: ~5 sec/puzzle for 5K iterations.

**Effort.** M (3 days).
**Risk.** S. Can never make a path longer (SA accepts only valid candidates).
**Payoff.** MEDIUM — TSP analog gets 3-7% locally; expect 1-3% here.

### P4.2 — Adversarial state mining

**Hypothesis.** BFS-d6 gives EXACT optimal distance for 19.4M states. Compute |V_m05(s) -

**Code sketch:**

```python
import torch


def mine_hard_states(model, bfs_table, batch_size: int = 8192, top_k: int = 100000):
    """Return list of (state_bytes, model_v, true_d, error) for the worst-predicted states."""
    model.eval()
    errors = []
    device = next(model.parameters()).device
    keys = list(bfs_table.table.keys())
    for i in range(0, len(keys), batch_size):
        batch_keys = keys[i : i + batch_size]
        states = torch.from_numpy(
            np.stack([np.frombuffer(k, dtype=np.int8) for k in batch_keys])
        ).to(device, dtype=torch.long)
        with torch.no_grad():
            preds = model(states).flatten().cpu().numpy()
        for k, p in zip(batch_keys, preds):
            true_d = len(bfs_table.table[k])
            errors.append((k, p, true_d, abs(p - true_d)))
    errors.sort(key=lambda x: -x[3])
    return errors[:top_k]
```

Then in next training run, oversample these states with weight 10× normal random walks.

**Effort.** S (1 day).
**Risk.** S. Standard hard-mining technique.
**Payoff.** 2-3%.

def online_learning_solve_loop(model, puzzle, test_pids, test_states, generators,
                                solved_state, finetune_every: int = 50,
                                finetune_steps: int = 200):
    """Solve pids in order; periodically fine-tune model on accumulated solves."""
    replay = []  # list of (state, optimal_path_so_far)
    for pid in sorted(test_pids):
        state = test_states[pid]
        path = solve(model, state)  # use current model
        if path is not None:
            replay.append((state, path))
            # Save intermediate states along the path for richer dataset.
            cur = state
            for i, m in enumerate(path):
                replay.append((cur, path[i:]))
                cur = puzzle.apply_move(cur, m)
        # Fine-tune periodically.
        if pid % finetune_every == 0 and len(replay) > 100:
