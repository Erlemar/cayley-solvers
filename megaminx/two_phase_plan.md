# Two-phase (Kociemba-style) megaminx solver

Implementation of Vlad Kuznetsov's two-stage method (CayleyPy Growth BFS group,
2026-06-15). External evidence: mean total solve length **< 80 at beam 2^17**
(vs single-stage ~91), **~78 @ 2^20**, and a merged submission of **71,797** --
below our current floor (73,441 local / 75,200 submitted). This reopens the
group-decomposition direction we designed (`group_decomposition_design.md`,
2026-05-09) but never ran to a verdict. It is orthogonal to all inference-side and
architecture-side work, and is the most promising lever against the 6M cluster
ceiling because it makes each phase an *easier search* rather than a better scorer.

## The method

Megaminx has 12 faces -> 24 generators. Pick 6 faces as the Phase-2 "free" set.

- **Phase 2** solves *within* the subgroup `H` generated by the 6 TOP faces
  (12 generators). `|H| ~ 2e42`, branching ~8.7, estimated diameter ~45.
  A plain V (walk-depth MSE on restricted-generator walks from solved).
- **Phase 1** drives an arbitrary scramble *into* `H`: get every **frozen** sticker
  (one no TOP face can move) home, treating the 85 TOP-movable stickers as
  don't-care. A **MaskedV**: movable sticker VALUES are masked to a sentinel, so
  many fully-colored states collapse to the same target (the coset). Full 24-gen
  walks, walk-depth MSE.

Inference: mask scramble -> Phase-1 beam (goal = frozen home) -> apply path to the
real scramble (now in `H`) -> Phase-2 beam (restricted gens, goal = solved) ->
concatenate -> **verify**.

Trade-off (acknowledged by Vlad): forcing the solution through `H` blocks some
optimal paths (like Kociemba), so it is not length-optimal -- but each sub-search
is far easier, so at fixed beam width it wins big. Asymptotically the single-stage
curve is steeper, so the gap may shrink at enormous beams; at achievable widths
(2^17-2^20) two-stage dominates.

## The decomposition (this repo)

From `megaminx/src/megaminx/decomposition.py` (U-bowl split), verified in
`tests/test_two_phase.py`:

- **Phase-2 free faces** = `TOP_HALF = {U, F, L, R, BL, BR}` -> 12 gens
  (`U,-U,F,-F,L,-L,BL,-BL,BR,-BR,R,-R`).
- **Frozen (Phase-1 goal)** = LL stickers, `face_set subset BOTTOM` = **35**.
- **Movable (don't-care)** = F2L + equator = **85**.
- Provable direction (tested): TOP moves never disturb the 35 frozen stickers.
  The converse (every frozen-home state is in `H`) is Vlad's size argument; it only
  affects *how often* Phase 2 can close, never correctness -- every solution is
  `verify_path`-checked.

Mask is **by sticker value**, not position: the state is a permutation
(solved == identity), so masking movable VALUES preserves exactly the frozen-sticker
placement (the sufficient statistic for Phase-1 distance); masking by position would
lose frozen stickers sitting in movable slots.

## Files

| File | Role |
|---|---|
| `src/megaminx/two_phase.py` | `MaskedV`, `build_phase2_puzzle`, `movable_frozen_positions`, `make_frozen_goal_check`, `two_stage_solve_one`, `load_two_phase_model` |
| `scripts/110_train_phase2.py` | train Phase-2 V (restricted puzzle, plain ResMLP) |
| `scripts/111_train_phase1.py` | train Phase-1 V (full puzzle, MaskedV, num_classes 121) |
| `scripts/112_two_stage_solve.py` | solve + verify + CSV; `--baseline-checkpoint` (1-stage compare), `--smoke-depth` (plumbing) |
| `configs/m_phase1_pretrain.yaml`, `configs/m_phase2_pretrain.yaml` | recipes |
| `tests/test_two_phase.py` | partition / restricted puzzle / frozen-invariance / mask / goal-check |

No changes to shared infra (`training.py`, `khoruzhii_search.py`, `data.py`,
`model.py`) -- masking lives in the `MaskedV` wrapper, restriction in a restricted
`Megaminx`, and the solver already accepts a custom `goal_check_fn`.

## Commands

Train (local 4090, fast recipe; ~minutes/100s-of-epochs each):

```
.venv/Scripts/python.exe megaminx/scripts/110_train_phase2.py \
  --config megaminx/configs/m_phase2_pretrain.yaml --output megaminx/models/m_phase2_v0
.venv/Scripts/python.exe megaminx/scripts/111_train_phase1.py \
  --config megaminx/configs/m_phase1_pretrain.yaml --output megaminx/models/m_phase1_v0
```

Plumbing smoke (shallow scrambles, weak models OK):

```
.venv/Scripts/python.exe megaminx/scripts/112_two_stage_solve.py \
  --phase1-checkpoint <p1>.pt --phase2-checkpoint <p2>.pt \
  --smoke-depth 8 --smoke-n 5 --beam 8192 --out megaminx/submissions/smoke.csv
```

Beam-width sweep + single-stage compare (reproduce Vlad's curve):

```
for B in 16384 65536 131072 262144 1048576; do
  .venv/Scripts/python.exe megaminx/scripts/112_two_stage_solve.py \
    --phase1-checkpoint <p1>.pt --phase2-checkpoint <p2>.pt \
    --baseline-checkpoint megaminx/models/m_dd_v0/epoch_0049.pt \
    --spread 21 --beam $B --bf16 --out megaminx/submissions/two_stage_b$B.csv
done
```

## Open knobs / follow-ups

- Phase split point: number of Phase-2 free faces (Vlad noted 5 free faces is
  slightly worse than 6). Currently 6 (TOP_HALF).
- "Orientation preselect" (Vlad's Phase-1 booster, our sym-ensemble specialized):
  run the 12 face-as-bottom rotations with a small pre-beam, pick best, then the
  main beam. Maps onto `beam_lab/beam_search_sympooled.py` -- a later add-on.
- Bellman refine on either phase (Vlad used pretrain only) -- only if quality needs it.
- TPU port (the JAX kernels) once local validates -- Phase 2 is a restricted-gen
  beam; reuses the existing kernel with a 12-gen move table.
